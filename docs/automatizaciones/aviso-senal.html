EJEMPLO 01 · AUTOMATIZACIÓN SIN IA

Aviso cuando aparece una señal de venta

Todos los días a las 18:00, el flujo consulta la API, se queda con los activos que tienen señal de venta y manda un correo con la lista. Si no hay ninguno, no manda nada. Es la automatización más simple que igual resuelve algo real: no tener que mirar el tablero todos los días.

5 NODOS 15 MIN NIVEL INICIAL N8N SALIDA: EMAIL
01

Qué resuelve

Mirar precios a mano todos los días es aburrido y se olvida. Este flujo hace exactamente lo que harías vos en dos minutos, pero sin acordarte: pide los datos, aplica un filtro y te avisa solo cuando hay algo para mirar.

Asunto: FIN·LAB · señal VENTA · 2026-10-26

Señal VENTA en la sesión 2026-10-26:

- JNJ (Johnson & Johnson): 117.88 USD · RSI 28.1

Muestra educativa fija de FIN·LAB. No es una recomendación de inversión.
El detalle que hace la diferencia: el correo solo sale si hay coincidencias. Un flujo que te manda “no pasó nada” todos los días termina en la carpeta de spam mental.
02

Cómo funciona

1

Cada día 18:00

Un disparador por horario. En n8n es el nodo Schedule Trigger.

ENTRA: la hora · SALE: una ejecución
2

Consultar API FIN·LAB

Un pedido HTTP GET a la URL pública. Devuelve ocho activos de ejemplo.

ENTRA: URL · SALE: JSON con data.tickers[]
3

Filtrar señales

Un nodo Code recorre los activos y deja solo los que tienen la señal buscada. También arma el texto del correo.

SALE: hasSignal, symbols, texto
4

¿Hay señales?

Un nodo If con dos salidas: verdadero y falso.

VERDADERO: sigue · FALSO: termina
5

Enviar aviso por email

Solo por la salida verdadera. La salida falsa va a Sin novedades, que no hace nada.

ENTRA: texto · SALE: un correo
03

Armalo paso a paso

Podés importar el archivo y completar cuatro cosas, o armarlo desde cero con los mismos nodos. Las dos formas enseñan, pero importar primero te deja ver el recorrido completo funcionando.

DESCARGAR WORKFLOW (.JSON) VOLVER AL ÍNDICE

  1. Importá el archivo en n8n: menú de workflows → Import from File → elegí aviso-senal.json.
  2. Revisá la URL. El nodo Consultar API FIN·LAB ya apunta a la API del curso (postgrado-ia.vercel.app). Cambiala solo si publicaste tu propio despliegue.
  3. Conectá el correo. Abrí el nodo Enviar aviso por email y creá la credencial SMTP. Poné tu dirección en from y to: la primera prueba te la mandás a vos.
  4. Ejecutá a mano. Botón Execute workflow. Mirá la salida del nodo Filtrar señales: tiene que decir hasSignal: true y el símbolo JNJ.
  5. Ajustá la señal. En el código del nodo Filtrar señales, la primera línea es const SENAL = 'VENTA'. Cambiala por 'COMPRA' o 'NEUTRAL' y volvé a ejecutar.
  6. Activá el flujo recién cuando el correo llegue bien. Antes no.

04

Hablá con la IA

Estos tres pedidos son los que realmente vas a necesitar: uno para entender, uno para escribir el código del filtro y uno para arreglar cuando algo falla. Copialos y completá lo que está entre corchetes.

PROMPT 1 · QUE TE EXPLIQUE EL PLAN
Antes de escribir código. Sirve para no aceptar un workflow a ciegas.
Quiero armar en n8n un flujo que todos los días a las 18:00 consulte https://postgrado-ia.vercel.app/api/market/summary y me mande un email solo si hay al menos un activo con signal === 'VENTA'.

Los datos vienen en data.tickers[], y cada activo tiene symbol, name, last, change_pct y rsi14.

Todavía no me escribas el JSON ni el código. Contame en 5 pasos qué nodo usarías en cada uno, qué información entra y qué sale, y qué credenciales necesito.
PROMPT 2 · EL CÓDIGO DEL FILTRO
Para el nodo Code. Pedile también el caso vacío.
Escribime el código JavaScript de un nodo Code de n8n en modo "Run Once for All Items" que:
- reciba la respuesta de la API en $input.first().json
- filtre los activos donde signal === 'VENTA'
- devuelva UN solo item con: hasSignal (boolean), symbols (texto separado por comas) y texto (el cuerpo del email, con un renglón por activo y su RSI)
- si la respuesta no trae data.tickers, tire un Error con un mensaje claro en español

Sin librerías externas. Comentá solo lo necesario y decime después cómo probarlo con el caso de cero coincidencias.
PROMPT 3 · CUANDO ALGO FALLA
Pegá el error real. No lo resumas.
Mi workflow de n8n tiene estos nodos: Schedule Trigger → HTTP Request → Code (filtro) → If → Email.

Al ejecutar a mano, el nodo Code falla con este error:
[PEGÁ ACÁ EL ERROR COMPLETO]

Y esta es la salida del nodo HTTP Request:
[PEGÁ ACÁ EL JSON, recortado si es muy largo]

Decime: 1) la causa más probable, 2) cómo la compruebo en una corrida manual, 3) el cambio mínimo en el código. No me reescribas todo el workflow.

Cómo saber si funciona

    
    
      
  • La salida del filtro muestra hasSignal: true y el símbolo esperado (en la muestra fija, JNJ).
    • 
      
  • El correo llega a tu propia casilla con el asunto y el renglón del activo.
    • 
      
  • Cambiá la señal a 'NEUTRAL' y volvé a ejecutar: tiene que llegar el correo con GGAL.
    • 
      
  • Probá el caso vacío: poné una señal que no exista ('NADA'). No debe enviar nada y el flujo no debe romperse.
    • 
      
  • Revisá la zona horaria de la instancia de n8n: el horario del disparador se calcula con la zona del servidor, no con la tuya.
    • 
    

  


  

    06
    
Límites de este ejemplo

    
    
      
  • La API devuelve una muestra fija: los números no cambian entre corridas. Para precios reales hay que cambiar la fuente de datos, no el resto del flujo.
    • 
      
  • Un correo por corrida como máximo. Si querés agrupar varios activos, eso ya lo hace el filtro.
    • 
      
  • No evalúa si conviene vender: solo avisa que la señal aparece. La decisión sigue siendo tuya.
    • 
      
  • Si la API no responde, el nodo HTTP falla y la corrida queda en rojo. Configurá Retry On Fail si te molesta.
    • 
    

    
Cuidado con el correo: si activás el flujo y te olvidás, vas a recibir un correo por día hábil. Empezá con un destinatario propio y un horario que puedas revisar.
