Precios del mercado a Google Sheets

El flujo convierte la respuesta de la API en filas y las agrega a una planilla. Es el puente entre una automatización y el análisis que hacés después a mano o en Colab: la automatización junta, la planilla acumula.

01

Qué resuelve

Toda automatización que solo manda mensajes se olvida. Una que guarda datos deja un rastro que podés graficar, comparar entre semanas y usar como entrada de otro proceso. Acá la planilla hace de memoria.

El concepto que hay que entender: en n8n, un item es una fila. Si el nodo Code devuelve 8 items, la planilla recibe 8 filas. Si devuelve 1 item con un arreglo adentro, recibe una sola fila con todo apilado. Casi todos los errores de este tipo de flujo son eso.
02

Cómo funciona

1

Cada día 18:30

Schedule Trigger. Después del cierre, cuando ya te interesa guardar.

SALE: una ejecución
2

Consultar API FIN·LAB

HTTP GET. Un solo item con los ocho activos adentro de data.tickers[].

SALE: 1 item
3

Aplanar activos

El nodo Code recorre el arreglo y devuelve un item por activo, con la fecha de sesión incluida.

SALE: 8 items
4

Agregar filas en Sheets

Google Sheets → Append. Escribe ocho filas nuevas debajo de las que ya había.

SALE: 8 filas en la planilla

El paso 3 es el que hay que mirar con atención: no “sube la respuesta”, la desarma. Esa es toda la técnica.

03

Armalo paso a paso

DESCARGAR WORKFLOW (.JSON)

  1. Prepará la planilla antes del flujo: creá una hoja con la fila 1 de encabezados fecha, symbol, nombre, ultimo, cambio_pct, volumen, rsi14, senal. Los nombres tienen que coincidir exactamente.
  2. Importá precios-a-sheets.json en n8n.
  3. Conectá Google en el nodo Agregar filas en Sheets: n8n te guía con OAuth. Después elegí el documento y la hoja desde los desplegables.
  4. Reemplazá la URL de la API por tu dominio.
  5. Ejecutá a mano y contá las filas nuevas: tienen que ser ocho, con la fecha de hoy.
  6. Ejecutá de nuevo. Vas a tener 16 filas. Eso no es un error: es append. En el punto 06 está cómo evitarlo si no lo querés.

04

Hablá con la IA

El pedido clave acá es de concepto, no de código: “por qué me guarda una sola fila”. Una vez que entendés items y filas, el resto sale solo.

PROMPT 1 · ENTENDER ITEMS Y FILAS
El malentendido que arruina este flujo.
En n8n tengo un HTTP Request que devuelve:
{ "ok": true, "data": { "session": "2026-10-26", "tickers": [ {symbol, name, last, change_pct, volume, rsi14, signal}, ... 8 en total ] } }

Después tengo un nodo de Google Sheets que agrega filas, pero me escribe una sola fila con todo apilado.

Explicame, sin escribir el workflow: 1) qué es un "item" en n8n y cómo se relaciona con una fila de la planilla; 2) por qué la respuesta del HTTP es un solo item; 3) qué tiene que hacer el nodo intermedio para que salgan 8 filas; 4) cómo compruebo, mirando la salida del nodo, cuántos items hay.
PROMPT 2 · EL CÓDIGO QUE APLANA
Para el nodo Code del paso 3.
Escribime el código de un nodo Code de n8n (Run Once for All Items) que:
- lea $input.first().json.data
- si no existe data.tickers, tire un Error claro en español
- devuelva un item por cada activo, con estas claves exactas: fecha (la session), symbol, nombre, ultimo, cambio_pct, volumen, rsi14, senal
- no agregue claves de más

Después decime cómo comprobar en la salida del nodo que hay 8 items y no uno, y cómo probarlo con una lista vacía.
PROMPT 3 · EVITAR DUPLICADOS
Cuando el flujo corre dos veces el mismo día.
Tengo un flujo en n8n que agrega 8 filas por día a Google Sheets (una por activo, con la fecha de sesión en la columna "fecha"). Si lo ejecuto dos veces, duplica las filas.

Comparame estas dos soluciones y decime cuál conviene para un flujo diario:
1) antes de agregar, buscar si ya hay filas con esa fecha y no agregar nada si existen
2) usar "append or update" con una columna clave fecha+symbol

Para la que recomiendes, contame qué nodos necesito, qué columna tiene que ser la clave y cómo pruebo que no duplica sin borrar la planilla. Tené en cuenta que la hoja puede llegar a tener miles de filas.

Límites de este ejemplo

    
    
      
  • Append no actualiza. Si el mismo día corrés dos veces, tenés 16 filas. Para evitarlo necesitás una columna clave y un nodo de búsqueda previa, o append or update.
    • 
      
  • Los encabezados son un contrato. Si cambiás el nombre de una columna en la planilla, las filas nuevas van a quedar con celdas vacías.
    • 
      
  • Una planilla no es una base de datos. Sirve para miles de filas, no para millones. Cuando crece, conviene pasar a una base real.
    • 
      
  • Cuotas de Google: hay límites de pedidos por minuto. Un flujo diario está lejísimos, uno cada minuto no.
    • 
      
  • Privacidad: la planilla la ve quien tenga el enlace. No guardes ahí datos de terceros sin permiso.
    • 
      
  • Los datos son de una muestra fija: todas las corridas van a escribir los mismos precios con fechas distintas. Sirve para practicar el circuito, no para analizar el mercado.
    • 
    

    
Ojo con la fecha: la muestra de la API devuelve la fecha de hoy en session, pero los precios no cambian. Si vas a graficar después, aclará en la planilla que los datos son de práctica.
