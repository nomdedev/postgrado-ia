Resumen de tu cartera a las 8 de la mañana

El flujo guarda tu lista de tenencias, pide los precios del día, calcula el valor de cada posición y el total, y te manda el resumen antes de empezar. Es la automatización que reemplaza abrir tres pestañas para hacer una cuenta que ya sabés hacer.

01

Qué resuelve

Acá aparece la idea central de casi toda automatización útil: cruzar tus datos con datos de afuera. Tus tenencias viven en una lista que escribís una vez; los precios llegan por HTTP. El flujo los junta y hace la cuenta.

Muestra educativa fija de FIN·LAB. No es una recomendación de inversión.
Por qué la lista va en un nodo aparte: “mis datos” y “datos externos” son dos cosas distintas. Si mañana comprás otro activo, editás un solo lugar y no tocás la parte que consulta la API.
02

Cómo funciona

1

Cada día 08:00

Schedule Trigger. Antes de la apertura, para que el resumen esté listo cuando lo busques.

SALE: una ejecución
2

Mi cartera

Un nodo Code que solo devuelve la lista de tenencias: símbolo y cantidad.

SALE: cartera = [{ symbol, cantidad }]
3

Consultar API FIN·LAB

HTTP GET. Devuelve los ocho activos con último precio y variación.

SALE: data.tickers[]
4

Calcular valor

El nodo Code más importante: cruza las dos listas por símbolo, multiplica cantidad por precio y suma. Si un símbolo no existe, falla con un mensaje claro.

SALE: total, filas, texto
5

Enviar resumen

Email. El asunto incluye el total, el cuerpo es el texto armado en el paso anterior.

SALE: un correo por día

Fijate que no hay ningún nodo de IA. Es a propósito: sumar multiplicaciones no necesita un modelo de lenguaje. Usar IA donde alcanza una multiplicación es la forma más cara de complicar algo.

03

Armalo paso a paso

DESCARGAR WORKFLOW (.JSON)

  1. Importá el archivo resumen-diario.json en n8n.
  2. Editá tu cartera en el nodo Mi cartera. Cada línea es { symbol: 'AAPL', cantidad: 10 }. Usá símbolos que existan en la API: AAPL, MSFT, JNJ, KO, PG, GGAL, YPF, PAM.
  3. Reemplazá la URL del nodo Consultar API FIN·LAB por tu dominio.
  4. Conectá el correo en Enviar resumen y poné tu dirección en from y to.
  5. Ejecutá a mano y hacé la cuenta con calculadora. Si el total no coincide, el problema está en el código, no en el correo.
  6. Activá el flujo. La primera corrida real la vas a ver al día hábil siguiente.

04

Hablá con la IA

El pedido más útil acá no es “hacé el flujo”: es “explicame cómo pasar datos de un nodo a otro”. Ese es el concepto que después se repite en todo.

PROMPT 1 · ENTENDER EL CRUCE DE DATOS
Para no copiar un código que no sabés qué hace.
Estoy armando un flujo en n8n con estos nodos: Schedule Trigger → Code ("Mi cartera", devuelve una lista de {symbol, cantidad}) → HTTP Request (devuelve data.tickers[] con symbol y last) → Code (calcula el valor) → Email.

Explicame en lenguaje simple:
1) cómo hace el segundo nodo Code para leer los datos de "Mi cartera" si ya pasaron dos nodos;
2) qué diferencia hay entre $input.first().json y $('Mi cartera').first().json;
3) qué pasa si el nodo HTTP devuelve dos items en lugar de uno.

No me escribas el workflow: quiero entender el concepto.
PROMPT 2 · EL CÓDIGO QUE CRUZA LAS LISTAS
Incluye el caso del símbolo inexistente, que es donde se rompe.
En un nodo Code de n8n (Run Once for All Items) tengo que cruzar dos listas:
- la cartera: [{ symbol: 'AAPL', cantidad: 10 }, ...], guardada en el nodo "Mi cartera"
- los precios: $input.first().json.data.tickers, cada uno con symbol, last y change_pct

Escribime el código que:
- arma una fila por posición con: symbol, cantidad, last, valor y change_pct
- redondea los importes a 2 decimales
- suma el total
- devuelve UN item con { total, filas, texto } donde texto es el cuerpo del email con un renglón por activo
- si un símbolo de la cartera no aparece en los precios, tira un Error que diga cuál símbolo falta

Sin librerías externas. Después decime cómo probarlo cambiando un símbolo por uno inexistente.

Cómo saber si funciona

    
    
      
  • Hacé la cuenta a mano con dos activos y compará con el total del correo.
    • 
      
  • Probá un símbolo inexistente (por ejemplo 'TSLA'): el flujo tiene que fallar diciendo cuál falta, no mandar un total incompleto.
    • 
      
  • Revisá los decimales: 10 × 308.43 tiene que dar 3084.3, no 3084.299999. Si ves colas de decimales, falta redondeo.
    • 
      
  • Mirá el nodo Calcular valor en la corrida manual: ahí ves total y filas antes del correo.
    • 
      
  • Confirmá la zona horaria del servidor de n8n: si dice 08:00 pero llega a otra hora, es eso.
    • 
    

  


  

    06
    
Límites de este ejemplo

    
    
      
  • No calcula ganancia real: para eso hace falta el precio de compra de cada posición, que este flujo no tiene. Agregalo a la lista y el cálculo es una resta más.
    • 
      
  • Una sola moneda: todos los precios se tratan como dólares. Si mezclás monedas, hace falta convertir antes de sumar.
    • 
      
  • La cartera está escrita a mano en el nodo. Si cambia todos los días, conviene leerla de una planilla.
    • 
      
  • No ejecuta órdenes. Solo informa. Una automatización que compra y vende sola es un problema de otro tamaño.
    • 
      
  • Los precios son de una muestra fija: sirve para practicar, no para decidir.
