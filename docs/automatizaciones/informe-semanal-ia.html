EJEMPLO 03 · UN MODELO DE LENGUAJE COMO UN PASO MÁS

Informe semanal redactado por IA

Los números los calcula el flujo; el texto lo escribe un modelo de lenguaje. El secreto para que no invente nada está en dos decisiones: pasarle solo hechos ya calculados y darle reglas explícitas sobre qué hacer cuando falta un dato.

6 NODOS 25 MIN NIVEL MEDIO REQUIERE API KEY SALIDA: EMAIL
01

Qué resuelve

Un informe semanal es un trabajo de redacción, no de cálculo. El flujo ya sabe los precios, las señales y la amplitud del mercado; lo que falta es contarlo en cinco renglones. Ahí sí tiene sentido un modelo de lenguaje: transformar una tabla en un párrafo, todas las semanas, sin que nadie se siente a escribirlo.

02

Cómo funciona

1

Cada viernes 17:00

Schedule Trigger con expresión 0 17 * * 5.

SALE: una ejecución por semana
2

Consultar API FIN·LAB

HTTP GET. Trae los ocho activos, el índice y la amplitud.

SALE: data.tickers[] + data.index + data.breadth
3

Preparar hechos

Un nodo Code convierte el JSON en un texto plano, ordenado, con todos los números que el modelo va a poder usar. Ni uno más.

SALE: hechos (texto)
4

Pedir informe al modelo

HTTP Request POST al proveedor. El cuerpo lleva dos mensajes: las reglas (system) y los hechos (user).

ENTRA: hechos · SALE: choices[0].message.content
5

Armar informe

Se queda solo con el texto y falla fuerte si vino vacío, en lugar de mandar un correo en blanco.

SALE: texto limpio
6

Enviar informe

Email con el texto del modelo.

SALE: un correo por semana
El mismo nodo sirve para cualquier proveedor. OpenAI, Anthropic, Gemini o un modelo local con Ollama: cambia la URL, el header de autenticación y la forma del cuerpo. El resto del flujo no se toca. Por eso conviene tener el paso 4 separado del paso 3.
03

Armalo paso a paso

DESCARGAR WORKFLOW (.JSON)

  1. Importá informe-semanal-ia.json en n8n.
  2. Reemplazá la URL de la API FIN·LAB por tu dominio.
  3. Creá la credencial del modelo en n8n: tipo Header Auth, nombre Authorization y valor Bearer TU_API_KEY. La clave vive ahí, nunca en el nodo.
  4. Elegí el modelo en el cuerpo del nodo Pedir informe al modelo. El archivo viene con gpt-4o-mini; cambialo por el que tengas habilitado.
  5. Ejecutá a mano y leé el nodo Armar informe. Después abrí el correo y compará tres números con la respuesta de la API.
  6. Activá solo cuando el texto te parezca confiable y no invente datos.

04

Hablá con la IA

Acá la IA hace dos trabajos distintos: escribe el informe y te ayuda a escribir el prompt que lo controla. El segundo pedido es el que casi nadie hace y el que más cambia el resultado.

PROMPT 1 · EL PROMPT DEL SISTEMA
Pedile que diseñe las reglas, no el texto.
Necesito el prompt de sistema para un modelo que redacta un informe semanal de mercado a partir de una tabla de datos que le paso en el mensaje del usuario.

Condiciones:
- máximo 120 palabras, un solo párrafo, español rioplatense, tono neutro
- puede usar SOLO los números que aparecen en el texto recibido
- si un dato falta, escribe "sin dato" y sigue
- no da recomendaciones de inversión, no predice precios, no menciona activos que no estén en la tabla
- no repite la tabla: la cuenta

Devolveme: 1) el prompt de sistema listo para copiar, 2) tres casos de prueba con datos incompletos, 3) una lista de las frases que NO debería producir nunca.
PROMPT 2 · EL CUERPO DEL PEDIDO HTTP
Para el nodo HTTP Request, con la expresión de n8n.
En n8n tengo un nodo HTTP Request (v4.2) que llama a un endpoint compatible con la API de chat completions.

Necesito el campo jsonBody exacto para:
- mandar un mensaje de sistema fijo (te lo paso abajo)
- mandar como mensaje de usuario el texto que viene de $json.hechos
- temperatura 0.2 y un máximo de 200 tokens

El texto de $json.hechos tiene saltos de línea y comillas: quiero la expresión en una sola línea, con el prefijo "=" y usando JSON.stringify, para que no se rompa el JSON.

Este es mi mensaje de sistema:
[PEGAR EL PROMPT DEL SISTEMA]

Decime también cómo configurar la credencial (Header Auth) y cómo leer la respuesta en el nodo siguiente.

Cómo saber si funciona

    
    
      
  • Elegí tres números al azar del correo y buscalos en la respuesta de la API. Si uno no está, el modelo inventó.
    • 
      
  • Romped el dato: borrá un campo en el nodo Preparar hechos. El informe debería decir “sin dato”, no completar el hueco.
    • 
      
  • Cortá la API: si el nodo HTTP falla, no debe salir ningún correo. Verificá que el flujo se detenga.
    • 
      
  • Mirá el nodo Armar informe: si el modelo devuelve texto vacío, tiene que lanzar el error que dice el código.
    • 
      
  • Guardá una corrida: el texto enviado y los hechos que le pasaste. Es la única forma de auditar después qué dijo y con qué datos.
    • 
    

  


  

    06
    
Límites de este ejemplo

    
    
      
  • Puede alucinar. Las reglas reducen el riesgo, no lo eliminan. Sin la verificación del punto 05, no lo actives.
    • 
      
  • El texto cambia entre corridas. Con temperatura baja cambia poco, pero nunca es idéntico. Si necesitás exactitud, no uses un modelo de lenguaje para redactar.
    • 
      
  • No le pases datos personales ni información que no puedas compartir con el proveedor del modelo.
    • 
      
  • Tiene costo por uso y depende de un servicio externo. Si el proveedor se cae, el flujo no manda nada: eso es correcto.
    • 
      
  • No es análisis financiero. Es un resumen de una tabla.
