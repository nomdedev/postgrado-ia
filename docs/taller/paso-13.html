    El consejo de agentes: que el desacuerdo se vea

    Un solo agente tiende a estar de acuerdo consigo mismo. Un consejo de agentes reparte el trabajo: uno analiza, otro audita y otro redacta. Lo valioso no es la coincidencia, es el desacuerdo que queda escrito antes de decidir.

    30 MINN8N3 AGENTESSALIDA: UN INFORME CON REPAROS
    ¿Les falta el agente? Este paso encadena tres agentes como el del paso 12. Sin uno que funcione, el consejo no arranca. VOLVER AL PASO 12

    Qué van a lograr

    Tres agentes encadenados en n8n y una pregunta de inversión que pasa por los tres. El resultado es un informe corto que dice qué se analizó, qué reparos hay y qué se decidió, con los números de la API a la vista.

    ROLAPORTAEJEMPLO
    Analistalos datos y una propuesta“Moderada: Sharpe 0,84, la mejor de las tres”
    Auditorel supuesto que falta“los datos son simulados; el Sharpe no se sostiene en una crisis”
    Redactorla respuesta en 5 líneasinforme con el reparo incluido, sin recomendación
    Sin el auditor, el informe sale limpio y engañoso. El rol que molesta es el que agrega valor.

    El prompt

    PROMPT · PASO 13
    Para diseñar los roles del consejo.
    Paso 13 de un taller de finanzas con n8n. Tengo un agente que consulta la API del curso y calcula Sharpe.

Quiero armar un consejo de tres agentes encadenados: analista → auditor → redactor.

Para cada rol escribime el prompt de sistema, con estas condiciones:
- el analista propone una cartera y muestra los números que usó
- el auditor busca el error, el dato faltante y el supuesto no dicho; no puede proponer otra cartera
- el redactor escribe 5 líneas para un cliente, incluye el reparo del auditor y no da recomendaciones de inversión
- si el auditor no encuentra nada, tiene que decirlo explícitamente y explicar qué revisó

Después decime qué pregunta de prueba hace visible la diferencia entre un solo agente y el consejo.
    Puente con el proyecto real: el diagrama “Un consejo de agentes para una decisión de inversión” muestra este mismo circuito con los roles y el orden de los pedidos.

    Qué hacer, clic por clic

    1. Dupliquen el agente del paso 12 tres veces en el mismo workflow: analista, auditor y redactor.
    2. Cambien solo el prompt de sistema de cada uno, con las reglas del prompt de arriba.
    3. Encadénenlos: la salida del analista entra al auditor, y la de los dos al redactor.
    4. Hagan una pregunta de inversión con datos de la API: “¿qué cartera conviene para un perfil moderado hoy?”.
    5. Comparen con el paso 12: corran la misma pregunta con un solo agente y guarden las dos respuestas.
    6. Marquen el reparo que encontró el auditor. Si no encontró ninguno, revisen si los roles están realmente diferenciados.

    Cómo comprobar

    • El auditor agrega algo: el informe final menciona al menos un supuesto, un dato faltante o un límite del análisis.
    • Los números son de la API: el Sharpe y los precios citados coinciden con la pestaña Carteras.
    • No hay recomendación: el texto describe métricas; no dice “comprá” ni “vendé”.
    • El costo se justifica: la respuesta es mejor que la del paso 12. Si no lo es, el consejo sobra.

    Si algo falla

    ¿Se trabaron después de tres intentos? Prueben el consejo con una sola pregunta y sin herramientas: si los tres roles dicen lo mismo, el problema es el prompt de sistema, no el encadenado.
    • Los tres coinciden en todo: tienen el mismo prompt. El auditor necesita una instrucción explícita de buscar el error.
    • El informe ignora al auditor: el redactor no está recibiendo su salida. Revisen el orden de los nodos y qué campo entra a cada uno.
    • Tarda demasiado o gasta de más: es el costo real de tres agentes. Bajen el modelo de los roles simples, como el redactor.
    • El auditor inventa un problema: pídanle que cite el dato o el supuesto exacto; si no lo puede citar, no cuenta.
