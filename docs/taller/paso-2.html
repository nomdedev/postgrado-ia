    • PASO 2 · SIN DATOS NO HAY ANÁLISIS

    Un año de precios simulados que no cambia

    La terminal genera 252 ruedas (un año hábil) para cada activo. Parecen aleatorias, pero salen iguales en cada recarga gracias a una semilla. Ojo con lo que garantiza: con el mismo código, cualquiera obtiene los mismos números. Cada grupo tiene su propio código (lo escribió su IA), así que sus números no van a coincidir con los de otro grupo.

    15 MINCONSOLASALIDA: finlab-v2.html
    ¿Llegan tarde o se rompió el archivo? Bajen la versión con la que termina el paso 1, guárdenla como finlab.html y arranquen este paso desde ahí. ⬇ BAJAR EL PUNTO DE PARTIDA (PASO 1)

    Qué van a lograr

    Todavía no se ve nada nuevo en la pantalla: los datos se generan “por detrás” y se muestran en la consola como una tabla de control.

    El prompt

    PROMPT · PASO 2
    Pegar debajo el archivo del paso 1.
    Paso 2. Agregá la capa de datos (todavía sin mostrarla en pantalla, solo en la consola):
- una lista TICKERS con símbolo, nombre, precio inicial aproximado y volatilidad anual de cada activo
- una función simulateSeries(ticker) que genere 252 días hábiles (lunes a viernes) terminando hoy, con {d: 'AAAA-MM-DD', c: cierre, v: volumen}
- retorno diario = tendencia/252 + volatilidad/√252 · z (normal estándar)
- usá un generador pseudoaleatorio con semilla (por ejemplo mulberry32) y semilla distinta por símbolo, para que los datos sean SIEMPRE los mismos
- imprimí en la consola una tabla con símbolo, primer cierre, último cierre y variación % del año

Explicame en 3 líneas, para alguien que no programa, qué es una semilla y por qué la necesitamos.

[pegar el archivo completo]

    Qué hacer, clic por clic

    1. Abran finlab.html con el Bloc de notas (clic derecho → Abrir con), seleccionen todo (Ctrl + A) y cópienlo.
    2. En el chat, peguen primero el prompt de arriba y, debajo, el archivo completo. Envíen.
    3. Reemplacen todo el contenido de finlab.html por la respuesta y guarden.
    4. Abran la página y la consola (F12 → Console). Tiene que aparecer la tabla.
    5. El auditor hace las comprobaciones de “Cómo comprobar” y, si todo está bien, guardan finlab-v2.html.

    Cómo comprobar

    Si la consola no deja pegar: la primera vez, Chrome y Firefox muestran un aviso de seguridad y no pegan nada. Escriban a mano la frase que pide el aviso (en Chrome suele ser allow pasting), presionen Enter y vuelvan a pegar. Es una protección normal del navegador: peguen solo código de este taller.
    • Recarguen tres veces (F5): la tabla muestra exactamente los mismos números.
    • Cuenten las ruedas: en la consola escriban simulateSeries(TICKERS[0]).length y presionen Enter. Tiene que dar 252.
    • Sin fines de semana: escriban simulateSeries(TICKERS[0]).slice(-7) y miren las fechas. No puede aparecer ningún sábado ni domingo.
    • Sentido común: los activos más volátiles (GGAL, YPF) tienen que moverse más en el año que KO o JNJ.
    Para discutir en grupo: ¿por qué un dato simulado sirve más que uno real para aprender? (Pista: dentro del grupo todos pueden verificar el mismo número, y nadie confunde el ejercicio con una recomendación.)

    Si algo falla

    ¿Se trabaron después de tres intentos? Esta es una versión que ya cumple todo lo de este paso. Pueden abrirla para comparar o bajarla y seguir con el próximo. VER EL RESULTADO ⬇ BAJAR LA VERSIÓN DE RESCATE
    • “simulateSeries is not defined”: la función quedó “encerrada” dentro del código de React. Pídanle a la IA: “Exponé TICKERS y simulateSeries en window para poder probarlas desde la consola”.
    • Los números cambian al recargar: la IA usó Math.random(), que no tiene semilla. Pidan que use solo el generador con semilla.
    • La página quedó en blanco: usen el prompt de rescate del paso 1.

    El flujo: cómo nace un precio simulado

    1

    Una lista de activos

    Ocho acciones, cada una con su precio inicial y cuánto suele moverse.

    2

    Una semilla

    Un número fijo que hace que el “azar” salga siempre igual con el mismo código.

    3

    Un año de precios

    252 días hábiles de cierres por activo, sin fines de semana.

    4

    Una tabla de control

    En la consola del navegador, para verificar antes de que haya pantalla.
